Upload photo albums from Google Drive\n2. Share unique links with customers\n3. Let customers like (♥) or star (⭐) photos\n4. View which photos customers selected\n5. Export selections for printing/editing\n\n### Why?\n**Before:** Sending Google Drive link is unprofessional, no customer interaction tracking\n\n**After:** Beautiful gallery, customers engage, studio knows what to print\n\n### Who?\n- **Admins:** Photography studio owners\n- **Users:** Customers (couples, families, etc.) viewing album\n\n### Where?\nOnline, responsive design (mobile first)\n\n### When?\n- **Phase 0 (Week 1-2):** Documentation & prototype\n- **Phase 1 (Week 3-5):** Frontend MVP\n- **Phase 2 (Week 6-8):** Backend API\n- **Phase 3 (Week 9-10):** Integration\n- **Phase 4 (Week 11-12):** Launch\n\n---\n\n## Core Principles (Remember These!)\n\n1. **Performance First** — Images < 1s, page < 2s\n2. **Image First** — 70-80% of screen is photos\n3. **Mobile First** — Responsive from 320px+\n4. **Simple** — 1 action per screen\n5. **Professional** — Clean, elegant, premium feel\n\n---\n\n## Tech Stack (Quick)\n\n**Frontend:** Next.js 14 + React 18 + TypeScript + Tailwind CSS + shadcn/ui\n\n**Backend:** Node.js + Express (or Next.js API) + PostgreSQL + Prisma\n\n**Storage:** Google Drive (photos) + AWS S3/CDN (optional)\n\n**Deployment:** Vercel (frontend), Railway/ECS (backend)\n\n---\n\n## Critical Rules\n\n🚫 **Never:**\n- Redesign without approval\n- Invent new features\n- Change user workflows\n- Duplicate code\n- Commit secrets\n- Push without tests\n\n✅ **Always:**\n- Read the docs first\n- Test your changes\n- Follow conventions\n- Ask if unsure\n- Move fast\n- Keep it simple\n\n---\n\n## How to Use This Docs\n\n### Scenario 1: \"I need to build the gallery page\"\n1.
