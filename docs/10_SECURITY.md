# 10 — Security\n\nSecurity design for Books View (Studio + Customer).\n\n---\n\n## Authentication\n\n### Studio (Admin) Login\n- **Method:** JWT tokens (stateless)\n- **Flow:**\n  1. Email + password → POST /auth/login\n  2. Server validates, returns JWT\n  3. Client stores JWT in localStorage/cookie\n  4. All requests include: `Authorization: Bearer {token}`\n- **Token expiry:** 7 days (refresh endpoint available)\n- **Password:** bcryptjs (salt rounds: 10+)\n- **2FA:** Optional (TOTP), recommended for pro users\n\n### Customer (Guest) Access\n- **Method:** Link-based (no login needed)\n- **Flow:**\n  1. Receive unique link: `https://books-view.com/album/{linkToken}`\n  2. Click link → Create guest session\n  3. If password-protected → Enter password → Get guest JWT\n  4. Guest JWT valid for 24 hours or until browser close\n- **No credentials needed** (frictionless experience)\n- **Rate limited** to prevent abuse\n\n---\n\n## Authorization\n\n### Studio Access Control\n- **Row-level security:** Studio can only access own data\n- **Database check:** Every query filters by `studio_id`\n- **Example:**\n  ```ts\n  // Only return albums owned by THIS studio\n  const albums = await db.album.findMany({\n    where: { studioId: req.user.studioId }\n  })\n  ```\n\n### Customer Access Control\n- **Album-level access:** Customer can only see album they were invited to\n- **Selection-level:** Customer can only view/edit their own selections\n- **No cross-album access:** Can't view data from other albums\n\n### API Key Access\n- **For integrations:** Optional API keys\n- **Read/write permissions:** Configurable per key\n- **Rate limit:** Stricter limits per key\n\n---\n\n## Data Protection\n\n### Encryption at Rest\n- **Google Drive tokens:** Encrypted (AES-256) in database\n- **API keys:** Hashed before storage (never reversible)\n- **PII:** Name, email stored in plaintext (acceptable with HTTPS)\n  - *Future: Tokenization for extra privacy*\n\n### Encryption in Transit\n- **HTTPS/TLS 1.2+** — All connections\n- **HSTS headers** — Force HTTPS (no fallback to HTTP)\n- **Certificate pinning** — Optional for mobile (future)\n\n### Database Security\n- **Parameterized queries:** Prisma prevents SQL injection\n- **Input validation:** Zod schemas on all inputs\n- **No raw SQL:** Never concatenate user input\n- **Connection pooling:** Secure, authenticated connections\n- **Backup encryption:** Database backups encrypted at rest\n\n---\n\n## API Security\n\n### Rate Limiting\n```\n- Studio API: 1000 requests/hour per studio\n- Public gallery API: 100 requests/minute per link\n- Auth endpoints: 5 failed attempts → 15min lockout\n```\n\n### CORS (Cross-Origin Resource Sharing)\n```ts\ncors({\n  origin: process.env.FRONTEND_URL,\n  credentials: true,\n  methods: ['GET', 'POST', 'PATCH', 'DELETE'],\n  allowedHeaders: ['Authorization', 'Content-Type']\n})\n```\n\n### CSRF Protection\n- Not needed (JWT-based, no cookies)\n- Stateless requests → No session fixation\n\n### Input Validation\n- **Zod schemas:** Define all inputs (frontend + backend)\n- **Type checking:** TypeScript catches most errors\n- **Sanitization:** XSS prevention (escape HTML)\n\n### Output Encoding\n- **JSON responses:** Automatically escaped\n- **React:** Automatic XSS prevention (JSX)\n- **HTML:** Avoid `dangerouslySetInnerHTML`\n\n---\n\n## File Upload Security\n\n### Photo Upload (Google Drive Sync)\n- **Source:** Trusted (Google Drive API)\n- **Validation:**\n  - File type: Only image MIME types (jpg, png, webp, etc.)\n  - File size: Max 50MB per image\n  - Dimensions: Max 10000x10000px\n- **Processing:** Resize with sharp (prevent DoS)\n- **Storage:** Store in S3 or Google Cloud Storage (encrypted)\n\n### Manual File Upload (Rare)\n- **Same validation as above**\n- **Quarantine:** Scan with VirusTotal (optional)\n- **Sandboxing:** Process in isolated container\n\n---\n\n## Link Security\n\n### Album Share Link\n- **Format:** `https://books-view.com/album/{linkToken}`\n- **linkToken:** Random 32-character string (cryptographically secure)\n- **Unpredictable:** No sequential/guessable IDs\n- **Expiry:** Optional (admin can set)\n- **Password:** Optional second layer of auth\n\n### Link Brute-Force Protection\n- **Rate limit:** 100 attempts/minute per IP\n- **After 10 fails:** Temporary block (15 mins)\n- **Logging:** Track failed attempts → Alert studio\n\n### Link Revocation\n- **Studio can instantly revoke** link\n- **Existing guests:** Lose access immediately\n- **Re-share:** Generate new link\n\n---\n\n## Google Drive Integration\n\n### OAuth Flow (Studio Setup)\n```\n1. Studio clicks \"Connect Google Drive\"\n2. Redirected to Google OAuth consent screen\n3. User approves → Google returns auth code\n4. Server exchanges code for refresh token\n5. Refresh token stored (encrypted) in database\n6. Studio can now sync photos\n```\n\n### Permissions Requested\n- `drive.readonly` — Read folder structure & photos\n- `drive.readonly.metadata` — Read file metadata\n- **Never request:** `drive` (full access)\n\n### Token Security\n- **Refresh token:** Stored encrypted, rotated periodically\n- **Access token:** Short-lived (1 hour), auto-refreshed\n- **Revocation:** User can revoke via Google Account settings\n\n### Photo Access\n- **No shared albums stored locally** (only references)\n- **Direct streaming:** Photos delivered directly from Google Drive (if public) or via authenticated endpoint\n- **No re-hosting:** Keep photos on Drive (studio owns data)\n\n---\n\n## Session Management\n\n### Studio Session\n- **Duration:** 7 days (auto-logout)\n- **Remember me:** Optional (30 days)\n- **Concurrent sessions:** Allowed (logout from one device only)\n- **Device management:** View active sessions, logout from all\n\n### Customer Session\n- **Duration:** 24 hours or until browser close\n- **Persistence:** localStorage (client-side only)\n- **No cross-device:** Each device gets separate token\n- **Auto-logout:** Closing tab → session ends\n\n---\n\n## Password Policy\n\n### Requirements\n- **Min 8 characters** (12+ recommended)\n- **Mix of:** Uppercase, lowercase, numbers, symbols\n- **No common patterns:** \"password123\", \"abc123\", etc.\n- **Breach checking:** Validate against Have I Been Pwned database\n\n### Password Reset\n1. User enters email → POST /auth/forgot-password\n2. Server sends email with **one-time reset link**\n3. Link expires in **15 minutes**\n4. Link is single-use (can't reuse)\n5. User sets new password\n\n---\n\n## PII & Data Privacy\n\n### What We Collect\n- **Studio:** Name, email, phone (optional), studio name, logo\n- **Customer:** Name (optional), email (optional), phone (optional)\n- **Photos:** Metadata only (filename, size, dimensions), photos stored on Google Drive\n- **Usage:** API calls, view timestamps, selection data (intentional)\n\n### Data Retention\n- **Active accounts:** Indefinitely (user's choice)\n- **Deleted accounts:** Anonymize after 30 days, hard delete after 1 year\n- **Cookies:** None (localStorage only, no tracking)\n- **Analytics:** Anonymous, no PII\n\n### GDPR Compliance (Europe)\n- **Right to access:** Download all personal data (JSON export)\n- **Right to erasure:** Delete account + all data\n- **Right to portability:** Export data format\n- **Data processing agreement:** Available for enterprise\n- **Privacy policy:** Clear, transparent language\n\n### CCPA Compliance (California)\n- **Right to know:** What data we have\n- **Right to delete:** Request deletion\n- **Right to opt-out:** No data sales (we don't sell data)\n- **Do Not Track:** Respect DNT header\n\n---\n\n## Incident Response\n\n### Security Incident Plan\n1. **Detection:** Alert triggered (intrusion, data breach, DDoS)\n2. **Containment:** Isolate affected service, prevent spread\n3. **Investigation:** Analyze logs, determine scope\n4. **Communication:**\n   - Notify affected users within 24 hours\n   - Transparency: What happened, what we're doing\n   - Recommended actions (change passwords, etc.)\n5. **Remediation:** Fix vulnerability, update systems\n6. **Post-mortem:** Document, improve systems\n\n### Contact\n- **Security email:** security@books-view.com\n- **Response time:** Within 24 hours\n- **Responsible disclosure:** No public disclosure for 90 days\n\n---\n\n## Monitoring & Logging\n\n### Logs Collected\n- **Auth events:** Login, logout, 2FA, password reset\n- **API calls:** Endpoint, user, timestamp, response status\n- **Errors:** Stack trace, context, severity\n- **File uploads:** User, filename, size, timestamp\n- **Data changes:** Album created/edited/deleted, selections added/removed\n\n### Log Retention\n- **Access logs:** 90 days\n- **Error logs:** 30 days\n- **Audit logs:** 1 year (for compliance)\n- **Encryption:** Logs encrypted at rest\n\n### Monitoring Alerts\n- Multiple failed login attempts → Alert studio\n- Unusual API activity → Alert admin\n- Rate limit exceeded → Block & notify\n- SSL certificate expiring → Automatic renewal reminder\n\n---\n\n## Third-Party Security\n\n### Vendors\n- **Vercel:** SOC 2 Type II, GDPR compliant\n- **PostgreSQL/RDS:** AWS managed, encrypted, backed up\n- **Google Drive API:** OAuth 2.0, official SDK\n- **Stripe (future):** PCI-DSS Level 1\n\n### Dependency Management\n- **npm audit:** Weekly automated scanning\n- **Snyk:** Real-time vulnerability alerts\n- **Automated updates:** Patch releases auto-merged\n- **Manual review:** Major versions reviewed by team\n\n---\n\n## Regular Security Practices\n\n✅ **Do**\n- Keep dependencies updated\n- Run security audits monthly\n- Review access logs quarterly\n- Rotate secrets annually\n- Test disaster recovery annually\n- Security training for team\n\n❌ **Don't**\n- Commit secrets to git\n- Use public WiFi for admin access\n- Disable HTTPS or HSTS\n- Log passwords or tokens\n- Share credentials via chat\n- Ignore security warnings\n\n---\n\n## Future Security Enhancements\n\n- [ ] Biometric login (fingerprint, face)\n- [ ]
