# 28. KHI PASSWORD BỊ LỘ — BOOKS VIEW

## 1. Mục đích

Nếu password dùng để truy cập/xác thực Album bị lộ, chỉ đổi password là chưa đủ.

Có thể đã tồn tại các Customer Session được tạo trước đó.

Vì vậy BOOKS VIEW cần có:

```text
Change Album Password
+
Revoke All Customer Sessions
```

Mục tiêu:

> Đổi password cũ và buộc các Customer Session liên quan phải xác thực lại bằng password mới.

---

# 2. Tình huống password bị lộ

Ví dụ:

```text
Album Password:
12345678
```

Password bị chia sẻ cho người khác.

Người đó có thể:

```text
Password
 ↓
Xác thực Album
 ↓
Customer Session
 ↓
ACTIVE
```

Sau đó Owner đổi password.

Nếu không revoke session cũ:

```text
Password cũ ❌
       │
       └── Session cũ vẫn ACTIVE ⚠️
```

Người đã xác thực trước đó có thể vẫn tiếp tục sử dụng session cũ nếu session chưa hết hạn.

---

# 3. Change Album Password

Chủ Album có thể chọn:

```text
Change Album Password
```

Ví dụ:

```text
New Password
[••••••••••••]

Confirm Password
[••••••••••••]

[Change Password]
```

Server phải:

```text
Validate
 ↓
Hash Password
 ↓
Save
```

Không lưu password dạng plaintext.

Sau khi đổi:

```text
Password cũ
↓
REVOKED ❌
```

và:

```text
Password mới
↓
ACTIVE ✅
```

---

# 4. Đổi password chưa đủ

Đây là nguyên tắc quan trọng.

Ví dụ:

```text
Password cũ bị lộ
        ↓
Người ngoài biết password
        ↓
Đã xác thực Album
        ↓
Server tạo Customer Session
```

Sau đó Owner đổi password:

```text
Change Album Password
```

Nếu không revoke session:

```text
Password cũ ❌
        │
        └── Customer Session cũ vẫn ACTIVE ⚠️
```

Vì vậy cần xử lý cả session.

---

# 5. Revoke All Customer Sessions

Cần có:

```text
Revoke All Customer Sessions
```

Mục đích:

> Hủy các Customer Session đang có quyền truy cập Album và buộc khách xác thực lại.

Luồng:

```text
Revoke All Customer Sessions
          ↓
Customer Sessions
          ↓
REVOKED ❌
```

Sau đó:

```text
Customer
 ↓
Truy cập Album
 ↓
Session không còn hợp lệ
 ↓
Yêu cầu xác thực lại
 ↓
Nhập Password mới
 ↓
Session mới ✅
```

---

# 6. Luồng hoàn chỉnh

```text
PASSWORD BỊ LỘ
      ↓
Change Album Password
      ↓
Password cũ ❌
      ↓
Password mới ✅
      ↓
Revoke All Customer Sessions
      ↓
Session cũ ❌
      ↓
Customer phải xác thực lại
      ↓
Nhập Password mới
      ↓
Session mới ✅
```

Đây là cách xử lý đầy đủ khi password bị lộ.

---

# 7. Nên tự động Revoke Sessions

Nên thiết kế để việc đổi password có tùy chọn:

```text
☑ Revoke all customer sessions
```

và nên bật mặc định.

Hoặc đơn giản hơn, sử dụng một hành động:

```text
[Change Password & Revoke Sessions]
```

Mục tiêu là tránh trường hợp Owner đổi password nhưng quên revoke session cũ.

Có thể hiển thị cảnh báo:

> Đổi mật khẩu sẽ vô hiệu hóa các phiên truy cập của khách hiện tại. Khách sẽ cần xác thực lại bằng mật khẩu mới để tiếp tục truy cập Album.

---

# 8. Không revoke Admin Session

Cần tách:

```text
Customer Session
```

và:

```text
Admin Session
```

Khi đổi Album Password:

```text
Change Album Password
        ↓
Revoke Customer Sessions
        ↓
Admin Session vẫn hoạt động ✅
```

Không được tùy tiện đăng xuất tài khoản Admin khỏi toàn bộ BOOKS VIEW.

Album Password là password của Album/Customer Access, không phải password tài khoản Admin.

---

# 9. Primary Customer

Nếu BOOKS VIEW có:

```text
Guest
Primary Customer
```

và Primary Customer được xác thực bằng Primary Password:

```text
Primary Password
 ↓
Primary Customer Session
```

thì khi đổi password cần revoke các Primary Customer Session liên quan.

Nếu có Customer Session khác, chính sách revoke phải được xác định rõ theo phạm vi của Album.

Tên:

```text
Revoke All Customer Sessions
```

được hiểu là các session của Customer liên quan đến Album, không phải Admin Session.

---

# 10. Audit Log

Các hành động cần được ghi vào Audit Log:

```text
ALBUM_PASSWORD_CHANGED
CUSTOMER_SESSIONS_REVOKED
```

Ví dụ:

```text
Actor:
studio@example.com

Album:
Wedding Minh & Lan

Action:
ALBUM_PASSWORD_CHANGED

Time:
28/08/2026 22:30

Result:
SUCCESS
```

Sau đó:

```text
Action:
CUSTOMER_SESSIONS_REVOKED

Scope:
All Customer Sessions
```

Không ghi:

```text
Password mới
Password cũ
Session Token
```

nguyên dạng vào Audit Log.

---

# 11. Giao diện đề xuất

Trong:

```text
Albums
 ↓
Settings
 ↓
Album Security
```

có:

```text
Primary Password

● Enabled

[ Change Password ]
```

Khi đổi:

```text
┌──────────────────────────────────────┐
│ Change Album Password                │
│                                      │
│ New Password                         │
│ [••••••••••••]                       │
│                                      │
│ Confirm Password                     │
│ [••••••••••••]                       │
│                                      │
│ ☑ Revoke all customer sessions       │
│                                      │
│ Khách đang đăng nhập sẽ phải xác     │

│                                      │
│ [Cancel] [Change Password]           │
└──────────────────────────────────────┘
```

Hoặc dùng một nút rõ ràng hơn:

```text
[Change Password & Revoke Sessions]
```

---

# 12. Trường hợp password và link cùng bị lộ

Nếu nghi ngờ cả password và Album Link đã bị lộ, có thể thực hiện:

```text
Rotate Album Link
+
Change Album Password
+
Revoke All Customer Sessions
```

Kết quả:

```text
Link cũ ❌
Password cũ ❌
Session cũ ❌
```

và:

```text
Link mới ✅
Password mới ✅
Session mới ✅
```

Đây là phương án reset mạnh quyền truy cập Album.

---

# 13. Không ảnh hưởng dữ liệu Album

Đổi password hoặc revoke session không được xóa:

```text
Photos
Selections
Comments
Likes
Stars
Cover
Album Settings
Customer Data
```

Mục đích chỉ là:

```text
Reset Access
```

không phải:

```text
Delete Data
```

---

# 14. Server-side Security

Không được chỉ xử lý bằng frontend.

Luồng phải là:

```text
Owner
 ↓
Change Album Password
 ↓
API
 ↓
Authentication
 ↓
Authorization
 ↓
Album Ownership / Permission
 ↓
Validate
 ↓
Hash New Password
 ↓
Update Password
 ↓
Revoke Customer Sessions
 ↓
Audit Log
 ↓
Response
```

Customer Session khi truy cập Album phải kiểm tra trạng thái hợp lệ ở server.

---

# 15. Checklist

```text
□ Có Change Album Password
□ Password mới được validate
□ Password được hash
□ Không lưu plaintext password
□ Password cũ bị vô hiệu hóa
□ Có Revoke All Customer Sessions
□ Customer Session cũ bị revoke
□ Customer phải xác thực lại
□ Session mới dùng password mới
□ Không revoke Admin Session tùy tiện
□ Guest và Primary Customer được phân biệt
□ Primary Customer Session được xử lý khi đổi Primary Password
□ Có thể tự động revoke session khi đổi password
□ Có cảnh báo cho Owner
□ Có Audit Log
□ Ghi ALBUM_PASSWORD_CHANGED
□ Ghi CUSTOMER_SESSIONS_REVOKED
□ Không ghi password vào Audit Log
□ Không ghi session token vào Audit Log
□ Không xóa Photos
□ Không xóa Selections
□ Không xóa Comments
□ Không xóa Album
□ Thao tác được kiểm tra ở server
□ Authentication được kiểm tra
□ Authorization được kiểm tra
```

---

# 16. Nguyên tắc cuối cùng

> **Password bị lộ → không chỉ đổi password. Phải xử lý cả các Customer Session đã được tạo bằng password cũ.**

Mô hình:

```text
             PASSWORD BỊ LỘ
                    ↓
          Change Album Password
                    ↓
              Password mới
                    ↓
       Revoke All Customer Sessions
                    ↓
               Session cũ ❌
                    ↓
          Customer xác thực lại
                    ↓
               Session mới ✅
```

Nếu nghi ngờ cả link bị lộ:

```text
Rotate Album Link
+
Change Album Password
+
Revoke All Customer Sessions
```

Kết quả:

```text
Link cũ ❌
Password cũ ❌
Session cũ ❌
```

trong khi:

```text
Link mới ✅
Password mới ✅
Session mới ✅
```

**Không xóa dữ liệu Album. Chỉ reset quyền truy cập.**
