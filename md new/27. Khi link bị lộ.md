# 27. KHI LINK BỊ LỘ — BOOKS VIEW

## 1. Mục đích

Mỗi Album có một `Album Link` để khách truy cập.

Nếu Studio nghi ngờ link đã bị:

```text
Gửi nhầm người
Chia sẻ công khai
Đăng lên mạng
Người ngoài biết được
Không còn muốn sử dụng link cũ
```

Studio phải có khả năng:

```text
Rotate Album Link
```

Mục tiêu:

> Thay link truy cập Album bằng một link mới và **vô hiệu hóa hoàn toàn link cũ**, trong khi không xóa Album hoặc dữ liệu bên trong.

---

# 2. Luồng Rotate Album Link

Ví dụ ban đầu:

```text
Link cũ
↓
/album/ABC123
↓
ACTIVE ✅
```

Studio thực hiện:

```text
Rotate Album Link
```

Sau đó:

```text
Link cũ
↓
/album/ABC123
↓
REVOKED ❌
```

và:

```text
Link mới
↓
/album/X9kP72...
↓
ACTIVE ✅
```

---

# 3. Link cũ phải bị vô hiệu hóa

Không được chỉ tạo link mới nhưng vẫn để link cũ hoạt động.

Không:

```text
Link cũ
+
Link mới
+
Cả hai đều hoạt động
```

Phải:

```text
ABC123
 ↓
REVOKED ❌
```

và:

```text
X9kP72...
 ↓
ACTIVE ✅
```

Nếu người nào đó vẫn giữ link cũ:

```text
/album/ABC123
```

server phải từ chối truy cập.

---

# 4. Rotate Link không xóa Album

Rất quan trọng:

```text
Rotate Link
≠
Delete Album
```

Album vẫn giữ nguyên:

```text
Album
├── Photos
├── Selections
├── Comments
├── Cover
├── Settings
└── Customer
```

Chỉ thay đổi:

```text
Access Link
```

---

# 5. Người đang có link cũ

Nếu Guest đang giữ link cũ:

```text
Guest
 ↓
/album/ABC123
 ↓
REVOKED ❌
```

Guest phải sử dụng:

```text
Link mới
↓
/album/X9kP72...
↓
ACTIVE ✅
```

Đây chính là mục đích của Rotate Link.

---

# 6. Rotate Link và Session

Nếu Album có các session đang hoạt động, có thể kết hợp:

```text
Rotate Link
+
Revoke Album Sessions
```

đặc biệt khi Studio nghi ngờ người ngoài đã truy cập.

Mục tiêu:

```text
Link cũ ❌
+
Session cũ phù hợp ❌
+
Link mới ✅
```

Việc revoke session phải tuân theo cơ chế Session Security của BOOKS VIEW.

---

# 7. Rotate Link phải thực hiện ở Server

Không được chỉ thay đổi URL bằng frontend.

Luồng:

```text
Studio
 ↓
Rotate Album Link
 ↓
API
 ↓
Authentication
 ↓
Authorization
 ↓
Album Ownership / Permission
 ↓
Generate New Token
 ↓
Revoke Old Token
 ↓
Save Database
 ↓
Audit Log
 ↓
Trả Link mới
```

Frontend chỉ hiển thị kết quả do server trả về.

---

# 8. Token mới phải khó đoán

Album Link nên sử dụng token:

```text
Random
Khó đoán
Đủ dài
```

Không nên sử dụng các giá trị dễ đoán như:

```text
/album/1
/album/2
/album/3
```

hoặc token tuần tự.

Ví dụ:

```text
/album/X9kP72mQa81...
```

Token mới phải được tạo bằng cơ chế random an toàn phía server.

---

# 9. Không dùng Database ID làm Access Link nếu không cần

Ví dụ database có:

```text
Album ID:
d6f55423-d3a9-4ca6-89c5-f8f021af05df
```

Không nhất thiết dùng trực tiếp ID này làm public access token.

Nên tách:

```text
Database ID
```

và:

```text
Album Link Token
```

Ví dụ:

```text
Album ID
d6f55423...

Album Link Token
X9kP72...
```

Mục đích là tách identifier nội bộ khỏi cơ chế truy cập Album.

---

# 10. Audit Log

Mỗi lần Rotate Link nên ghi Audit Log:

```text
ALBUM_LINK_ROTATED
```

Ví dụ:

```text
Actor:
user@example.com

Album:
Wedding Minh & Lan

Action:
ALBUM_LINK_ROTATED

Time:
28/08/2026 22:30

Result:
SUCCESS
```

Không ghi nguyên token bí mật cũ/mới vào Audit Log nếu không cần thiết.

---

# 11. Giao diện

Trong:

```text
Albums
 ↓
Settings
 ↓
Album Security
```

có:

```text
Album Link

https://booksview.vn/album/X9kP72...

[Copy Link]    [Rotate Link]
```

Khi bấm:

```text
Rotate Link
```

nên hiện cảnh báo:

> **Đổi link Album?**  
> Link hiện tại sẽ bị vô hiệu hóa ngay lập tức. Những người đang sử dụng link cũ sẽ không thể truy cập Album bằng link đó nữa.

Nút:

```text
[Hủy]    [Rotate Link]
```

Sau khi thành công:

```text
✓ Đã tạo link mới.
Link cũ đã bị vô hiệu hóa.
```

---

# 12. Khi Rotate Link thất bại

Nếu server không thể tạo link mới hoặc cập nhật database:

```text
Rotate Link
 ↓
ERROR
```

Không được để trạng thái nửa vời:

```text
Link cũ bị revoke
+
Link mới chưa được lưu
```

Nên thực hiện thao tác cập nhật theo cách đảm bảo tính nhất quán dữ liệu.

Người dùng nhận thông báo an toàn:

```text
Không thể đổi link. Vui lòng thử lại.
```

Chi tiết kỹ thuật chỉ ghi ở server log.

---

# 13. Không làm mất dữ liệu khách

Rotate Link không được làm mất:

```text
Photos
Selections
Comments
Likes
Stars
Cover
Album Settings
```

Ví dụ:

```text
Album
 ↓
Rotate Link
 ↓
Photos vẫn còn
Selections vẫn còn
Comments vẫn còn
```

Chỉ thay đổi quyền truy cập thông qua link.

# 16. Nguyên tắc cuối cùng

> **Rotate Album Link = thay ổ khóa truy cập Album.**

Mô hình:

```text
Link cũ
↓
REVOKED ❌
```

và:

```text
Link mới
↓
ACTIVE ✅
```

**Album, ảnh, lựa chọn và dữ liệu khách không bị xóa.**

Chỉ quyền truy cập thông qua link cũ bị thu hồi.

Mục tiêu:

```text
Link bị lộ
 ↓
Studio Rotate Link
 ↓
Link cũ mất hiệu lực
 ↓
Link mới được tạo
 ↓
Album tiếp tục hoạt động an toàn
```
